# Відповіді на контрольні питання

### 1. Що таке Git?
**Git** — це розподілена система керування версіями (DVCS), яка дозволяє відстежувати зміни в файлах проєкту, зберігати історію редагувань, повертатися до попередніх станів та ефективно працювати над кодом спільно з іншими розробниками.

---

### 2. В якому статусі можуть перебувати файли при роботі з Git?
У Git файли можуть перебувати у двох основних станах: **Untracked** (невідстежувані) та **Tracked** (відстежувані). Відстежувані файли, у свою чергу, поділяються на такі статуси:

* **Untracked** — нові файли, про існування яких Git знає, але ще не відстежує їхні зміни.
* **Staged / Index** — файли, підготовлені до коміту (додані командою `git add`).
* **Committed / Unmodified** — файли, зміни в яких уже збережені в локальній базі даних (коміті).
* **Modified** — відстежувані файли, у які були внесені зміни з моменту останнього коміту, але вони ще не підготовлені до збереження.

---

### 3. Для чого використовується команда add?
Команда `git add` використовується для переведення файлів із робочої директорії до индекса (staging area). Вона додає нові або змінені файли до списку тих, які увійдуть до наступного коміту.

---

### 4. Для чого використовується команда status?
Команда `git status` відображає поточний стан робочої директорії та индексу. Вона показує, які файли змінені, які підготовлені до коміту (Staged), а які Git наразі не відстежує (Untracked).

---

### 5. Для чого використовується команда commit?
Команда `git commit` використовується для фіксації (збереження) підготовлених змін (зі staging area) у локальному репозиторії. Вона створює знімок (snapshot) проєкту з унікальним ідентифікатором (хэшем) та описом.

---

### 6. Для чого використовується команда init?
Команда `git init` використовується для ініціалізації нового репозиторію Git у поточній папці. Вона створює приховану системну директорію `.git`, де зберігаються всі налаштування та історія версій проєкту.

---

### 7. Що необхідно писати в коментарях комітів?
У коментарях до коміту (`-m "повідомлення"`) необхідно стисло та зрозуміло описати, **які саме зміни були внесені** та **з якою метою** (наприклад: `Add README file`, `Fix login bug`, `Update styling`). Повідомлення має допомагати іншим розробникам зрозуміти суть фіксації.
